# 发送端屏幕修复与新增代码说明

日期：2026-10-27。工程：`finalboardTX`。硬件：当前连接的 STM32F746G-DISCO，ST-Link 序列号 `0669FF3731324B4D43133623`。

## 1. 黑屏原因

这次不是界面没有生成。你重新生成的工程已经切换为 **CMake + ARM GCC**，`cmake/touchgfx/CMakeLists.txt` 已包含 GUI 源码、字体、文本和 TouchGFX 库；此前关于 IAR 尚未接入的结论已不适用于当前构建。

修复前通过 ST-Link 读取到：

- CPU 在 FreeRTOS 空闲任务中运行，`uwTick` 正常推进，HCLK 为 200 MHz。
- CFSR/HFSR 故障寄存器均为 0；本次不是 MPU 异常导致的停机。
- PI12 显示使能和 PK3 背光均为高电平，LTDC 已启用，读取地址为 `0xC0000000`。
- SDRAM 的刷新寄存器 `FMC_SDRTR` 为 **0**。
- 源码只有 defaultTask，没有启动执行 TouchGFX 绘制循环的任务。

因此主要缺了两个环节：**作为画布的外部 SDRAM 没有完成芯片启动；负责绘制画面的 TouchGFX 任务没有运行。** 背光亮着也不能因此显示出界面。

证据：`debug_evidence/baseline.txt`。修复前板上 1 MiB Flash 已备份为 `debug_evidence/baseline_flash.bin`。

## 3. SDRAM 如何启动

当前本地 HAL 的 `HAL_SDRAM_Init()` 只初始化控制器、时序和引脚，没有替你发送外部 SDRAM 芯片所需的完整启动命令。

本次 `Board_SDRAM_Init()` 的顺序为：

1. 校验 HCLK=200 MHz、SDCLK=HCLK/2、CAS=3、16 位数据、8 列位/12 行位、4 banks。
2. 发送时钟使能命令，等待至少 100 μs（代码等待 1 ms）。
3. 全部 bank 预充电。
4. 发送 8 次自动刷新。
5. 写入模式寄存器：突发长度 1、顺序访问、CAS=3、单次写突发。
6. 设置刷新计数 `floor(100000000 × 0.064 / 4096) − 20 = 1542`。

之后对两个实际使用的帧缓冲写入不同测试图样并读回比对，再清零。每块大小 `480×272×2=261120` 字节，两块合计 522240 字节；地址分别为 `0xC0000000` 和 `0xC0040000`。自检在 LTDC 初始化之前执行，不会在正常绘制期间覆盖用户画面。

这验证的是当前两个帧缓冲的启动读写，不代表做过整块 8 MiB 内存的长期压力测试。若以后改变主时钟、SDRAM 时钟或存储芯片，需一起复核时序和刷新值；当前代码会对关键配置不一致主动报错。

## 4. 为什么图形任务要独立运行

当前工程启用了 FreeRTOS，`MX_TouchGFX_Process()` 会进入等待 VSYNC 的长期循环，不会立即返回。它必须在一个真实运行的任务中执行。

`Board_DisplayStartTask()` 使用静态任务控制块和 4096 个 `StackType_t` 的栈（Cortex-M7 上为 16 KiB），不从原有的 32 KiB FreeRTOS 动态堆再分配这块栈。原来的 defaultTask 继续按原配置启动 USB 和 LwIP。

完整启动关系如下：

```text
HAL 与系统时钟初始化
  → GPIO、FMC 控制器配置
  → SDRAM 芯片启动、双缓冲自检和清零
  → I2C3、LTDC 等外设初始化
  → TouchGFX 框架初始化
  → 创建原有任务和独立 GUI 任务
  → FreeRTOS 启动
  → GUI 任务处理 VSYNC、触摸和绘制
  → 完成绘制后开启显示与背光
```

## 5. 触摸初始化为什么延后

接入驱动后曾定位到一个实际时序问题：TouchGFX 在调度器启动前调用 `STM32TouchController::init()`，此时 FreeRTOS 的队列/信号量创建已将 BASEPRI 设为 `0x50`。若在这里调用 `HAL_Delay(200)`，HAL 计时中断被屏蔽，延时不会结束，整个启动流程停住。

证据：`debug_evidence/touch_init_delay.txt`，PC 位于 `HAL_Delay`，`uwTick=153`，`BASEPRI=0x50`。

修正后，`init()` 只标记待初始化；第一次由 GUI 任务执行 `sampleTouch()` 时，才进行等待和 I2C 操作。此时调度器已运行，`osDelay()` 和 I2C 超时都有正常计时基础。

驱动读取 ID 寄存器 `0xA8`，确认 ID 为 `0x51`，将芯片设为轮询模式，然后持续读取触点。I2C 的 7 位地址为 `0x38`，传入 STM32 HAL 时使用左移后的 `0x70`。驱动仅返回坐标和按下状态，具体命中哪一个按键由 TouchGFX 判断。

## 6. 界面目前实现的功能

- D1、D2、D3 分别保存自己的频率参数，初值均为 1000 Hz。
- 点击通道后用数字键输入；支持清空、退格、确认、取消。
- 仅允许 100–10000 Hz 的整数，空输入和越界输入不保存。
- 切换通道会丢弃尚未确认的输入；取消会恢复当前通道已保存值。
- 已确认的参数保存在 RAM，复位后回到初值。
- **尚未把这三个参数连接到三路硬件波形输出，也没有掉电保存。** 这保持了此前“先做界面和参数”的要求。
- 本次没有验证或实现新的 ADC 采集、UDP 数据发送、USB 文件操作。
